## Product contract to preserve

The immutable canonical catalog and the causal pipeline remain unchanged:

```text
BehaviorEvent[] -> deriveFeatures(last 8 targeted events)
               -> detectState
               -> derivePolicy
               -> render the same catalog with a different presentation
```

The three states remain `EXPLORE`, `COMPARE`, and `FOCUS`. The 27-second replay,
ON/OFF shared evidence, monotonic manual interaction, Pause/Resume/Stop/Reset,
manual takeover, local SVG art, local fonts, collapsed inspectors, keyboard
navigation, focus preservation, reduced motion, and the three required viewports
remain in scope.

## Source-backed defects

### P0-1: nested deployment path

`vite.config.ts` has no `base`, Playwright uses the root URL, and the current suite
does not prove `/uiadapt_demo/`. The production default must be
`/uiadapt_demo/`. Direct navigation, reload, JavaScript/CSS/font loading, asset
status, console, and replay behavior must be tested at that path.

### P0-2: Adaptive OFF copy leak

`src/App.tsx` currently derives one `copy` from `detectedState` and uses it for both
consumer storefront presentation and diagnostics. With detected `FOCUS` and applied
`EXPLORE`, the consumer can see FOCUS copy while adaptation is OFF. The design
separates `detectedCopy` from `presentationCopy`; only the latter may drive
merchant-facing title/description.

### P0-3: purchase evidence is not product-specific

`FeatureSnapshot.purchaseSupportSignals` aggregates signals from every product.
That permits a Nova purchase-support event to support an Aurora-dominant FOCUS.
The snapshot gains `purchaseSupportSignalsByProduct: Record<ProductId, number>` and
FOCUS uses only the dominant product's count.

## Approved P1 refinements

1. A stable `demo-stage` contains the merchant storefront and adaptive presentation.
   The COMPARE surface is part of that stage and visible at the canonical desktop
   transition without repeated automatic scrolling.
2. `showComparison` is true only for applied `COMPARE`. FOCUS hides comparison and
   presents decision-support information for the focused product while retaining all
   product controls in the DOM.
3. The merchant is named `Atelier Audio`; `Powered by UIAdapt` identifies the
   adaptive technology layer. Existing controls and diagnostic surfaces remain.
4. A new CI workflow and a new v4.1 publication verification document record fresh
   results. Existing v4.0 evidence is not rewritten.

## Design decisions and boundaries

- `derivePolicy` remains a pure function. Its explicit policy is:
  `showComparison = appliedState === "COMPARE"`.
- Adaptive OFF still calculates and reports detected state and features; it only
  forces `appliedState` and consumer copy to `EXPLORE`.
- `purchaseSupportSignalsByProduct` is initialized for all three IDs and computed
  in one pass over the evidence window. No catalog object is mutated or duplicated.
- The nested base is a production default. A deliberately documented environment
  override may be used for local tooling, but tests and CI use `/uiadapt_demo/`.
- Replay scrolling, if needed, occurs once when Watch starts. State transitions do
  not trigger additional scrolling. Reduced motion uses immediate movement.
- No backend, authentication, checkout, analytics, ML, recommendation service,
  server rendering, or bidirectional downgrade model is introduced.
- v4.2 downgrade/hysteresis remains a documented backlog item only.

## Test-first contracts

Each changed behavior follows `RED -> minimal implementation -> GREEN -> relevant
regression -> refactor while green`.

### P0 RED contracts

- Nested direct navigation/reload loads the app and local assets under
  `/uiadapt_demo/` with zero failed requests and zero console errors.
- Canonical replay with OFF ends in `detectedState=FOCUS` and
  `appliedState=EXPLORE`; merchant title/description equal initial EXPLORE copy,
  while diagnostic state copy reports FOCUS. ON applies FOCUS copy.
- Aurora-dominant evidence with Nova-only purchase support cannot enter FOCUS.
  Aurora-dominant evidence with Aurora purchase support can enter FOCUS when all
  existing thresholds and dwell conditions are satisfied.
- `derivePolicy("FOCUS", true, "aurora-one").showComparison` is false.

### P1 RED contracts

- COMPARE surface is inside the stable demo stage and visible in the 1440x900
  viewport at the canonical transition.
- COMPARE shows comparison support; FOCUS hides it and shows decision support.
- Catalog text and values remain byte-equivalent across all states and modes.
- `Atelier Audio` and `Powered by UIAdapt` are separately discoverable.
- CI runs the nested path suite on Node 22/Ubuntu Chromium and publication document
  records fresh command output and limitations.

## Acceptance and failure gates

Acceptance requires all P0 and P1 contracts, all baseline commands from a fresh
source, `npm audit --omit=dev --audit-level=high`, `git diff --check`, a clean
worktree except intentional evidence/docs, and a new v4.1 evidence directory.

Automatic failure includes any product data mutation, different ON/OFF evidence,
root-only deployment proof, hidden test failures, external runtime requests,
secrets, live-server changes, unresolved Important review findings, or a claim of
human product clarity without the actual three-person test.

Product clarity remains `PRODUCT_CLARITY = NOT_VERIFIED` unless three independent
non-developers actually perform the 30-second test. It is not simulated.
